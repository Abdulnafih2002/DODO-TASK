Screenshots & Evidence Checklist

The brief asks for screenshots, recordings, and an architecture diagram. This page explains exactly what to capture, which command or URL to use, what each screenshot should show, and where to save it.

Before You Begin

Real screenshots captured on your own machine are the most convincing. Following this checklist should make the evidence collection a quick and straightforward process.

Screenshot on macOS: Press Cmd + Shift + 4, then drag a box around the required area. The screenshot will be saved to your Desktop.
Screen recording on macOS: Press Cmd + Shift + 5, then select Record Selected Portion.
Raw evidence is already available: Every command's raw output has been saved as text inside the relevant screenshots/ and evidence/ folders. For example: task1-harden/screenshots/task1-verification.txt. These files prove the same results, while screenshots make the evidence easier for the reviewer to understand.

Confirm the cluster is running

cd ~/Documents/GitHub/DODO-TASK && kubectl get nodes

Refer to RUN-AND-TEST.md when the cluster is not running.

Architecture Diagram

The brief requests an architecture diagram created using draw.io, Excalidraw, or a similar diagramming tool. Three formats are available inside docs/architecture/.

architecture.drawio

Format: Editable draw.io diagram

Open it using diagrams.net through File → Open, or use the Draw.io Integration extension in VS Code.

architecture.png

Format: Rendered image

Double-click the file to preview it. It can be inserted directly into the README, report, or presentation.

architecture.md

Format: Mermaid source

Contains three diagrams and renders automatically when viewed through GitHub.

Exporting an edited draw.io diagram: Open architecture.drawio at diagrams.net, then select File → Export as → PNG.
